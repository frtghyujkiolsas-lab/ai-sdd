## 验收口径

这个项目的验收重点不是“是否适合直接进企业生产”，而是是否证明了完整产品闭环：

```text
需求明确
→ 原型可看
→ 接口可调
→ 后端可跑
→ 前后端可联调
→ 结果可交付
```

## 需求追踪结论

| 需求 | 对应交付物 | 验收方式 | 当前结论 |
| --- | --- | --- | --- |
| REQ-01 填写信息并上传照片 | 上传页、`POST /api/generate` | AC-01 正常提交 | 已覆盖 |
| REQ-02 标准化生活照 | HivisionIDPhotos 调用、`id_photo` | AC-02 输出检查 | 已覆盖 |
| REQ-03 合成并导出工牌 | HTML/CSS 模板、`badge_png` | AC-03 下载与版式检查 | 已覆盖 |
| REQ-04 可理解的异常反馈 | 上传页 / 处理页、`error` | AC-04 异常场景检查 | 已覆盖 |

这张表是当前版本的交付收口：需求不是“写过就算”，而是要能在实现与验收中留下对应证据。后续新增能力必须先补充需求、规格和验收场景，再进入实现。
